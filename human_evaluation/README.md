# Paper Trace 人工评估

## 发放

将 `html/human-evaluation/evaluator-01.html` 至 `evaluator-05.html` 分别交给五位评审者，每人只拿自己的一份。页面是独立文件，可直接用电脑浏览器打开，也可放到静态网站上。`evaluator-pages.zip` **只包含这五个 HTML**，没有 PDF、自动标签或研究者清单。

每个页面提供两个固定版本的 arXiv 完整 PDF 链接及版本信息链接；没有下载、裁剪或分发论文。链接的论文编号和版本来自已完成标注的数据；本次未联网逐个检查可访问性或人工核验论文内容。原始目录大多数页数仍为空，所以页面仅在已有页数时显示页数。

评审者无需输入姓名或文字，以 E01–E05 标识。请由组织者另行保存编号与真实评审者的对应关系。

## 中英文切换

五份页面均在右上角提供 **English / 中文** 切换，首次按浏览器语言选择，之后记住选择。

- 英文模式：说明、问题、选项、导航、保存状态及提示全部使用英文，展示原有英文修改描述。
- 中文模式：界面使用中文，每个维度同时展示中文译文和英文原文。论文标题及方法、数据集名称保留原名。
- 150 个不同 pair 的 2,100 条修改描述均由 AI 助手直接翻译，译文内嵌于 HTML；运行时不调用翻译服务、不依赖仓库权限。
- 翻译对象是此前已中性化的候选描述，原英文和原始标注 JSON 保持不变。译文不是已核验事实；如有歧义，应对照英文和论文原文。
- 切换语言不改变任务顺序、选项编码或已有答案。两种语言共用同一份进度，导出的 JSON 可跨语言继续导入。

`translation_sources.json` 固定对应英文，`translations_zh.json` 保存逐条中文。构建要求 150 对、每对 14 条全部覆盖，且当前英文与翻译输入完全匹配，避免缺译或错配。

## 已确定的分配

| 项目 | 数量 |
| --- | ---: |
| 不同论文 / 不同 pair | 150 / 150 |
| 总体标签为 major improvement | 75 |
| 总体标签为 minor improvement | 75 |
| 单人评审的 pair | 100（50 major + 50 minor） |
| 双人评审的 pair | 50（25 major + 25 minor） |
| 总评审任务 | 200 |
| 每人任务 | 40（20 major + 20 minor） |
| 每人单评 / 双评任务 | 20 / 20 |
| 任意两位评审者共享的 pair | 5 |

五个会议固定为 ICLR2026、ICML2026、ACL2026、CVPR2026、ECCV2026。每个会议抽取 15 major + 15 minor，分给每人各 4 major + 4 minor。每个类别的 15 对中，5 对双评、10 对单评。共享任务对评审者不可见，题序分别打乱。

随机种子：`20260918`。在每个会议、每个总体改善类别中，先对符合条件的论文均匀抽样，再从该论文该类别的已完成 pair 中随机选一对。全研究同一论文只选一次；major 层先抽，minor 层排除已选论文。**抽样标签是整体 `improvement.change`，不是某一个维度的 change，也不是论文的最大标签。** 没有重跑或修改既有筛选规则。

这是按会议和类别均衡的核验样本，不是各会议规模成比例的总体流行率样本。当前按会议平衡分配，未按评审者专长匹配。

## 页面问题

每对论文共 16 个必答单选项（没有预选项）：

1. 14 个维度分别判断候选修改描述：属实 / 部分属实 / 不属实 / 无法判断。
2. 后一版本相对前一版本整体质量：明显改善 / 略有改善 / 无实质差别 / 略有退步 / 明显退步 / 无法判断。
3. 核验依据：看过两个版本相关内容 / 只看一个版本 / 只看描述 / 访问或材料有问题。

前 14 项核验的是**描述的事实准确性**，不是要求某个维度必须发生变化，也不是要求赞同自动分类。描述“内容保持不变”同样是待核验事实。整体改善单独判断，不由准确性分数相加产生。

“无法判断”算作已填写，**不表示完成了实质验证**。分析时需另外报告不确定性和证据覆盖，不应直接把页面完成率当作正确率。

## 标签遮蔽与描述处理

评审 HTML 使用字段白名单：论文标题、论文编号、两个具体版本的链接、14 个候选描述，以及问卷文本。**不嵌入总体标签、维度标签、整体改善理由、来源会议、其他评审者编号或共享状态。** 前后版本的时间顺序没有遮蔽。

候选描述来自原始 `justification`。构建程序去掉部分直接判断修改幅度的词；`neutral_edits.json` 保存进一步审阅后去掉的质量评判性语句。数值、章节图表定位、科学主张、统计显著性、否定及不确定性尽量保留。修改前后的文本逐条记录在研究者 manifest 中，原始判断 JSON 没有改动。

这是**提供描述、隐藏分类的核验**。描述本身仍会反映修改规模，不应声称消除了所有提示效应。人工评估的描述准确性对应呈现出来的文本，不能直接等同于未经编辑的原始理由准确性。

`organizer-manifest.json` 包含所有标签、任务映射、源文件哈希和描述编辑记录，只给组织者使用；已加入 `.gitignore`。不要把该文件交给评审者。

## 保存和回收

- 每次点击保存到当前浏览器的 localStorage，各评审份和内容版本独立。
- 评审者点击“导出答案 JSON”，把下载文件交给组织者；页面不自动上传。
- 可导出未完成进度；换设备、浏览器或文件位置时，先导出，再在同一编号页面导入。
- 导入会校验研究编号、评审编号、任务内容哈希、论文编号与选项。有现有答案时，替换前需要确认。
- 浏览器禁用本地存储时会显示提示，仍可作答并导出。请定期导出备份，同一浏览器只打开一个副本。
- 本次双语升级保留原 `assignment_hash`，原版页面的答案仍可导入；另外记录 `presentation_version` 和 `presentation_hash` 区分双语材料。发放后请冻结页面及译文版本。

导出数据包含 `study_id`、`schema_version`、`evaluator_id`、`assignment_hash`、`answers`、导出时间与完成情况。`answers[pair_id]` 保存 14 个 `criteria`、`overall`、`evidence_scope` 及首次/最后作答时间；未作答的整体项为 `null`、维度项缺省。所有 40 个任务都会包含在导出中。另含中英文选项编码映射、导出时的 `interface_language`、材料版本和哈希；双语版中作答过的 pair 还含 `last_answer_language`，表示最后一次修改答案时的界面语言，不表示该 pair 全程仅用此语言。

## 重建和检查

依赖 Python 与 Node，无第三方包。

```sh
python3 human_evaluation/build.py
python3 human_evaluation/test_build.py
node human_evaluation/test_app.cjs
```

源数据固定为 `res/published/check_diff_5conf_20260919/`。构建记录输入和输出哈希并验证所选判断文件。自动检查覆盖：抽样分层、重复率、不同论文、每人/每会议配额、固定版本链接、页面不含标签、双评材料一致、嵌入转义、断点恢复、导入/导出、错误文件、本地存储失败及全量完成。双语检查另外覆盖 2,100 条译文完整性、原任务哈希不变、全部 200 个分配任务的中英文渲染、切换语言保留答案，以及旧版答案兼容。

前端行为测试使用轻量 DOM harness；不等同于真实浏览器的视觉或端到端测试。
